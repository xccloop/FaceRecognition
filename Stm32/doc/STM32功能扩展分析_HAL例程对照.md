## 三、建议优先添加的功能（按优先级排序）

### 优先级 P0 —— 核心执行功能（门禁必需）

#### 1. 继电器 / 电磁锁控制 【参考：实验1 跑马灯】

- **需求：** 识别成功 → 开门；识别失败 → 不开门；超时 → 保持锁死
- **硬件：** 1 路 GPIO 输出（推挽）→ 驱动继电器模块 → 电磁锁
- **实现要点：**
  - 配置 PB0（或其他空闲引脚）为推挽输出
  - 开门时序：高电平 → 延时 3 秒 → 低电平（自动关锁）
  - 必须在 FreeRTOS 任务上下文中操作，避免在 ISR 中长时间延时
  - 增加安全逻辑：心跳超时时绝不开门
- **现有基础：** 与 LED 控制几乎相同，GPIO 输出代码可直接复用

#### 2. 蜂鸣器告警 【参考：实验2 蜂鸣器】

- **需求：** 陌生人告警、多人告警、Pi 离线告警 → 不同声音模式
- **硬件：** 1 路 GPIO 输出 → 有源蜂鸣器（或 PWM → 无源蜂鸣器）
- **实现要点：**
  - 有源蜂鸣器：GPIO 高低电平控制通断（最简单）
  - 无源蜂鸣器：TIM PWM 输出不同频率实现不同音调（更灵活）
  - 告警模式建议：
    - 陌生人：短促"嘀-嘀-嘀"（3 声）
    - 多人：急促连续"嘀嘀嘀嘀嘀嘀"
    - Pi 离线：长间隔"嘀———嘀———"
    - 识别成功：短"嘀"一声
  - 使用 FreeRTOS 软件定时器控制蜂鸣器时序，不阻塞主循环
- **现有基础：** LED 闪烁逻辑可复用为蜂鸣器控制逻辑

#### 3. 按键输入 【参考：实验3 按键输入】

- **需求：**
  - 出门按钮：室内按下直接开门（无需人脸识别）
  - 管理员按键：长按 3 秒进入管理模式（注册/删除用户）
  - 紧急按钮：触发报警或强制开门
- **硬件：** 2-3 路 GPIO 输入（上拉）+ 按键到 GND
- **实现要点：**
  - 软件消抖（20ms 延时确认）
  - 支持短按 / 长按区分
  - 在 FreeRTOS 任务中轮询或使用 EXTI 中断 → 队列
  - 出门按钮：任何状态下按下都开门（最高优先级）
- **现有基础：** 需要新建按键扫描任务或使用现有定时器回调

### 优先级 P1 —— 增强功能（提升体验和可靠性）

#### 4. ✅ UART DMA 收发 【已完成 - 2026-05-23】

- **实现：** 已从 `D:\DMA-RingBuffer UART Framework` 移植完整三层架构：
  - `uart_port.c/h` — SPL 硬件端口层（DMA1 C5 循环模式 + USART1 IDLE 中断）
  - `uart_dma.c/h` — DMA-UART 抽象层（以 RingBuffer 为 backend）
  - `uart_api.c/h` — UART 便利层（互斥锁保护的阻塞/异步收发 + printf 重定向）
  - `ringbuffer.c/h` — 通用环形缓冲区（2 的幂大小）
- **硬件：** USART1 (PA9-TX, PA10-RX) + DMA1 C5
- **验证：** PC 串口助手 HEX 模式全 5 条命令通过
- **详见：** `Stm32/doc/stm32-dma-uart-debug.md`

#### 5. OLED 显示屏 【参考：实验12 OLED（I2C）】

- **需求：** 实时显示识别结果、时间、设备状态
- **硬件：** 0.96 寸 OLED（SSD1306），I2C 接口（SCL/PB6, SDA/PB7）
- **显示内容建议：**
  - 第 1 行：当前时间（需 RTC）
  - 第 2 行：识别结果（姓名/陌生人/无人）
  - 第 3 行：系统状态（正常/离线/告警）
  - 第 4 行：最近识别记录
- **实现要点：**
  - I2C 软件模拟（不与硬件 I2C 冲突时也可用硬件 I2C）
  - 在 FreeRTOS 任务中刷新显示（1 秒更新一次即可）
  - 需要移植 SSD1306 驱动和 6x8/8x16 字库
- **现有基础：** 无，需要新增 I2C 驱动和显示任务

#### 6. RTC 实时时钟 【参考：实验15 RTC】

- **需求：** 为识别记录提供时间戳，支持定时功能
- **硬件：** STM32 内置 RTC + 外部 32.768kHz 晶振 + 后备电池
- **实现要点：**
  - 配置 LSE 外部低速晶振
  - 提供 `get_timestamp()` 接口（返回 Unix 时间戳或格式化字符串）
  - 与 OLED 显示联动
  - 可存储到 FLASH 中作为识别日志时间戳
- **注意：** F103 的 RTC 比较简单（只有秒计数器），需要在软件层做日历转换
- **现有基础：** 无，需要新增 RTC 初始化

#### 7. 窗口看门狗 【参考：实验7 窗口看门狗】

- **需求：** 当前已实现独立看门狗（IWDG），但窗口看门狗（WWDG）提供更精细的超时控制——喂狗不能太早也不能太晚，能检测到主循环跑飞但中断仍能喂狗的情况
- **硬件：** STM32 内置 WWDG
- **实现要点：**
  - WWDG 与 IWDG 可同时使用，双重保险
  - WWDG 在 FreeRTOS 最高优先级任务中喂狗
  - WWDG 超时产生中断 → 可在中断中记录故障信息再复位
- **现有基础：** 已有 IWDG，WWDG 作为补充

### 优先级 P2 —— 扩展功能（按需选用）

#### 8. FLASH 模拟 EEPROM 【参考：实验33 FLASH 模拟 EEPROM】

- **需求：** 存储以下掉电不丢失的配置参数：
  - 设备 ID / 通信地址
  - 串口波特率配置
  - 开门延时时间
  - 心跳超时阈值
  - 最近的识别日志（环形缓冲）
- **硬件：** STM32 片内 Flash 最后几页
- **实现要点：**
  - 利用片内 Flash 最后 1-2 页（F103C8T6 共 64 页 × 1KB）
  - 实现写平衡（wear leveling）简单版本：双页交替
  - 提供 `load_config()` / `save_config()` 接口
  - 注意 Flash 写入时必须关闭全局中断
- **风险：** Flash 擦写寿命约 1 万次，不适合频繁写入的日志
- **现有基础：** 无

#### 9. 外部中断（门磁 / 人体红外）【参考：实验4 外部中断】

- **需求：**
  - 门磁传感器：检测门是否被强制打开（未授权开门）
  - 人体红外传感器（HC-SR501）：检测门口是否有人
- **硬件：** 2 路 EXTI 中断输入（PA4/PA5 等）
- **实现要点：**
  - EXTI 中断触发 → 发送事件到 FreeRTOS 队列
  - 门磁：门关闭 = 低电平，门打开 = 高电平
  - 逻辑：如果门打开但未收到开门指令 → 触发非法闯入告警
- **现有基础：** 需要新增 EXTI 配置和事件处理逻辑

#### 10. ADC 光敏传感器 【参考：实验20 光敏传感器】

- **需求：** 根据环境光自动调节 LED 亮度（夜间调暗，白天调亮），或检测到夜间时自动开启补光灯
- **硬件：** 光敏电阻 + ADC 通道（PA1 等）
- **实现要点：**
  - ADC 单次转换 + DMA 或定时触发
  - 光强阈值判断 → 自动控制补光
- **现有基础：** 无

#### 11. 串口 IAP 固件升级 【参考：实验47 串口 IAP】

- **需求：** 现场固件升级，无需拆机接 SWD/JTAG
- **硬件：** 无额外硬件，利用现有 USART1 与 Pi 通信
- **实现要点：**
  - Bootloader 占用 Flash 前 8-16KB
  - 应用代码从 0x08002000 开始
  - Pi 通过自定义协议发送 .bin 固件
  - 需要与 Pi 端配合（Pi 发升级指令 → STM32 进入 bootloader）
- **风险：** 升级失败可能导致变砖，需要可靠的校验和回滚机制
- **现有基础：** 无，工作量较大

## 七、关于 HAL 库与标准外设库的差异

### 关键事实

- **当前项目：** 使用 STM32 标准外设库 (FWlib 3.5 / `stm32f10x.h`)
- **参考例程：** 使用 HAL 库 (`stm32f1xx_hal.h`)
- **不兼容：** HAL 库和标准外设库的函数命名、初始化方式完全不同，不能混用

### 迁移影响

| 方面 | 标准库 (当前) | HAL 库 (参考例程) |
|------|-------------|-----------------|
| GPIO 初始化 | `GPIO_InitTypeDef` + `GPIO_Init()` | `HAL_GPIO_Init()` |
| USART 收发 | `USART_SendData()` / `USART_ReceiveData()` | `HAL_UART_Transmit()` / `HAL_UART_Receive()` |
| 中断处理 | 手动写 `USART1_IRQHandler()` | HAL 提供通用 IRQHandler + 回调 |
| DMA | `DMA_InitTypeDef` + `DMA_Cmd()` | `HAL_DMA_Init()` + `HAL_DMA_Start()` |
| 代码量 | 更底层、更精简 | 更抽象、代码量更大 |

### 建议

**短期方案（推荐）：** 参考 HAL 例程的**概念和逻辑**（怎么配置外设、什么时序），但用**标准外设库 API** 实现。CMA UART 就是按此方式完成的。

**长期方案（可选）：** 将整个工程迁移到 HAL 库，可以：
- 直接复用正点原子例程的驱动代码
- 获得更好的可移植性（换 STM32 系列只需改 HAL 配置）
- 缺点：工作量大，需要重写所有现有代码
