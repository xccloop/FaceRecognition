# IWDG 独立看门狗

## 在这个项目中的作用

IWDG（Independent Watchdog）是 STM32 的**最后一道保险**。如果程序跑飞、任务死锁、中断风暴等原因导致核心循环停止，IWDG 超时后会强制复位 MCU，让系统自愈。

对应代码：`Stm32/User/main.c` — `IWDG_Init()` 和 `vUartRxTask()` 中的喂狗

## 核心原理

### 硬件机制

- IWDG 使用独立的 LSI 时钟源（~40kHz），不依赖系统时钟——即使主时钟挂了，看门狗照跑
- 一个递减计数器，计到 0 就产生复位信号
- 程序必须定期"喂狗"（重装载计数器），证明自己还活着

### 项目中的配置

```c
// main.c — IWDG_Init()
IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);   // 允许配置（默认写保护）
IWDG_SetPrescaler(IWDG_Prescaler_256);           // 预分频 256
IWDG_SetReload(625);                             // 重装载值
IWDG_ReloadCounter();                             // 加载初始值
IWDG_Enable();                                    // 启动（一旦启用，软件无法关闭！）
```

计算公式：

```
超时时间 = (Prescaler / LSI频率) × Reload
        = (256 / 40000) × 625
        = 4 秒
```

配置后 IWDG 立即启动，**软件无法关闭**（硬件保证）。必须在 4 秒内喂狗，否则复位。

### 喂狗位置

```c
// main.c — vUartRxTask() 循环尾部
for (;;) {
    // ... 收数据、解析帧、处理命令 ...

    IWDG_ReloadCounter();  // ← 喂狗
}
```

### 为什么喂狗放在这个位置

vUartRxTask 是核心任务——收 Pi 的帧、解析、分发、执行。如果这个任务卡死了（比如死锁、死循环、阻塞在某个不响应的外设上），**整个系统等于死了**。

- 喂狗在循环末尾 = 只有一整轮流程都跑完才喂狗
- 极端情况：任务在循环中间卡住 → 喂狗停止 → 4 秒后复位 → 系统自愈

### IWDG 与 WWDG 的区别

| 特性 | IWDG | WWDG |
|------|------|------|
| 时钟源 | 独立 LSI（~40kHz） | 系统时钟 PCLK1 |
| 关闭方式 | 硬件无法关闭 | 软件可关闭 |
| 复位时机 | 计数器归零 | 计数器低于窗口值时提前触发 |
| 适用场景 | 死循环、死锁（粗粒度） | 时序违规（细粒度） |
| 喂狗窗口 | 无（随时可喂） | 有（必须在窗口内喂） |

项目用 IWDG 就够了——目标就是检测"核心任务有没有卡死"。

### 喂狗注意事项

```c
IWDG_ReloadCounter();  // 放最后
```

- **不要在 ISR 中喂狗** — 如果主程序卡死了但定时器中断还在响，ISR 喂狗会让看门狗失效
- **不要在多处喂狗** — 会被"局部正常"误导，检测不到真正卡死的位置
- **喂狗只在一处，且必须是核心路径的终点**

## 要学到什么程度

- 理解 IWDG 独立于系统时钟的意义
- 能根据 LSI 频率、预分频、重装载值算出超时时间
- 理解"喂狗位置"的学问：放在哪里决定了能检测到什么故障
- 知道 IWDG 一旦启用就关不掉 — 硬件级别的安全保证
