# 四端协同人脸识别门禁系统

## 一句话概述

设计并实现了一套四端协同人脸识别门禁系统，**负责树莓派边缘推理引擎与 STM32 门锁终端（FreeRTOS）**，小程序与 Windows 后台借助 AI 辅助完成，全链路打通并稳定运行。

## 技术架构

```
微信小程序 ──HTTP──> Windows 后台 ──HTTP──> 树莓派4B ──UART──> STM32F103
 (AI辅助)         (AI辅助)          (★ 核心)       (★ 核心)
```

## 核心工作（树莓派 + STM32）

### 树莓派 4B — 边缘 AI 推理引擎

**当前部署：两进程分工**

| 进程 | 技术 | 用途 |
|------|------|------|
| `facerec run`（C++） | ncnn + ARM NEON | 实时推理：摄像头采集 → 检测 → 识别 → UART 输出 → MJPEG 推流 |
| `pi_server.py`（Python） | Flask + ONNX Runtime | 注册 API :5000：接收 Windows 照片 → 提取特征 → 存入 .bin 特征库 |

两个进程通过共享 `features/` 目录交换数据——C++ 进程每 5 秒自动热加载新注册的特征。

**从 Python 到 C++ 的重写历程**

> 第一版推理管线全部用 Python + ONNX Runtime 实现。实际部署后暴露三个瓶颈：
> - 推理仅 **5 FPS**（Python 逐帧全分辨率检测 + 三重循环解码）
> - 推流进程与推理进程**争抢摄像头**（两个进程都想独占 `/dev/video0`）
> - MJPEG **文件中转导致画面卡死**（推理进程停止写文件 = 推流进程反复发旧帧）
>
> 这些不是"Python 比 C++ 慢"的问题，而是多进程架构 + Python 解释器开销 +
> 文件中转 IO 三个因素叠加的结果。用 C++ 重写后，单进程 + 内存直传 + ncnn
> ARM NEON 加速，帧率从 5 FPS 提升到 25-30 FPS，同时消灭了抢设备和画面卡死。

- 基于 **ncnn** 部署 SCRFD 人脸检测 + MobileFaceNet 特征提取
- C++ 单进程管线：摄像头采集 → 检测 → 特征提取 → IOU 多目标跟踪 → 连续帧去抖确认 → 结果输出
- 内置 MJPEG 视频推流（raw socket + TCP_NODELAY，内存直接传递），特征库热加载（std::mutex 并发保护）
- 修复 ncnn Reshape 后关键点通道对齐问题，输出《ncnn 关键点修复记录》文档
- Python 注册服务保留 ONNX 引擎（复用模型，不做实时推理，性能要求低）

### STM32F103ZET6 — 门锁执行终端

- **FreeRTOS** 多任务：UART 接收任务 + 心跳检测定时器 + 帧超时保护
- **DMA 串口**：TX 链式 DMA + RX 环形 DMA + IDLE 中断，基于 RingBuffer 的 UART DMA 数据缓冲机制
- **自定义二进制帧协议**：COBS 编码（零字节帧分隔）+ CRC8 校验（256 字节查表），在 C（STM32）、C++（树莓派）、Python（测试）三端实现一致，45 个 pytest 用例全部通过
- 工程加固：DMA ORE 自动恢复、IWDG 独立看门狗、静态内存分配（避免动态内存碎片）、5ms 字节间超时保护

### 通信链路可靠性设计

| 链路 | 可靠手段 |
|---|---|
| STM32 ↔ 树莓派 UART | CRC8 帧校验、COBS 帧定界、DMA ORE 恢复、IWDG 超时复位 |
| Windows → 树莓派 HTTP | SQLite 持久化重试队列、指数退避（2s/5s/10s）、去重检查 |

## 辅助工作（AI 辅助完成）

- **微信小程序**：拍照上传、扫码配网、隐私授权合规（借助 AI 生成 + 搜索资料调试）
- **Windows 后台**：FastAPI + SQLAlchemy + SQLite 后端；Vue3 + Element Plus 管理面板；pywebview 桌面壳（借助 AI 生成框架，手动联调打通）

## 专业背景关联

汽车电子专业出身，熟悉嵌入式实时系统、串行通信协议与底层驱动。本项目将车载领域积累的**实时性思维、协议设计能力和可靠性工程方法**应用于边缘 AI + 门禁控制场景，打通了从 AI 推理到物理执行的完整链路。

## 待吃透的知识清单

> 范围限定：树莓派端 + STM32 端 + 网络传输（SSH 等），不含 UI 部分。

### 树莓派端 — Linux 环境与 C++ 推理管线

| 知识项 | 要学到什么程度 |
|---|---|
| Linux 基础 | 文件系统、权限模型、进程管理、Shell 脚本——能在无桌面的 Pi 上独立操作 |
| SSH | 免密登录、端口转发、scp 传文件、config 配置——日常唯一的远程入口 |
| C++ 编译工具链 | g++ 编译选项、CMake 基础、静态/动态链接——能自己写 CMakeLists 编译 ncnn 项目 |
| ncnn 推理框架 | 模型加载→推理→后处理全流程，理解 blob/mat/extractor 三个核心概念 |
| 人脸检测（SCRFD） | anchor-free 检测原理、多尺度特征融合、stride 与感受野、NMS 后处理 |
| 人脸识别（MobileFaceNet） | 特征提取网络结构、L2 归一化、余弦相似度匹配 |
| OpenCV / V4L2 | 摄像头采集、图像缩放/颜色转换、JPEG 编解码 |
| 多线程 | `std::thread`、`std::mutex`、读写锁——特征库热加载的并发模型 |
| systemd 服务 | 写 service 文件、开机自启、崩溃自动重启、日志查看（journalctl） |
| MJPEG 推流 | HTTP multipart 响应格式、raw socket 编程、TCP_NODELAY |

### STM32 端 — 嵌入式实时系统

| 知识项 | 要学到什么程度 |
|---|---|
| ARM Cortex-M3 基础 | 中断向量表、NVIC、SysTick、寄存器操作——能看懂参考手册 |
| FreeRTOS | 任务创建/调度、软件定时器、消息队列、静态内存分配——能用在这些场景 |
| DMA | 环形模式、IDLE 中断、half-transfer 中断、ORE 错误恢复——本项目 UART 的核心机制 |
| UART 串口 | 波特率、数据帧格式、TTL 电平——物理层到协议层的完整理解 |
| COBS 编码 | 原理（消除 0x00 → 用 0x00 做帧分隔符）、编解码实现——**自定义协议的基础** |
| CRC-8 校验 | 多项式、查表法实现、检错能力——**保证帧完整性的防线** |
| IWDG 看门狗 | 独立时钟源、超时复位、喂狗时机——**最后一道保险** |

### 通信链路 — 协议与可靠性

| 知识项 | 要学到什么程度 |
|---|---|
| 二进制帧协议设计 | 帧头/帧尾、长度字段、校验字段、转义机制——COBS+CRC 是本项目的实践答案 |
| 串口可靠性 | 字节丢失、帧不同步、缓冲区溢出——每种故障模式及应对方案 |
| HTTP 协议基础 | 请求/响应格式、multipart/form-data、状态码——Windows↔Pi 通信的载体 |
| 指数退避重试 | 为什么不能固定间隔重试、退避因子怎么选——同步队列的设计依据 |

### 建议学习顺序

```
1. SSH + Linux 基础        （先能连上 Pi）
2. C++ 编译 + ncnn 跑通    （能把模型跑起来）
3. 人脸检测/识别原理        （理解模型输入输出）
4. MJPEG + 多线程          （理解完整管线）
5. systemd 部署            （让程序变成服务）
   ↓
6. STM32 外设基础（GPIO→UART→DMA）
7. FreeRTOS（任务→定时器→队列）
8. COBS + CRC8 协议实现
9. DMA 环形缓冲 + IDLE 中断
10. IWDG + 故障恢复
   ↓
11. 两端联调：协议一致性验证
12. 端到端可靠性测试
```
