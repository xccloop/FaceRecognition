# 四端协同人脸识别系统 — 总体方案

## 一、系统总览

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  手机端   │────►│ Windows  │────►│ 树莓派4B │────►│  STM32   │
│ 小程序    │     │  后台    │     │  核心    │     │  执行端   │
│ 人脸采集  │     │ 管理+转发│     │ 识别推理  │     │  动作响应  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                                        │
                                        ▼
                                   ┌──────────┐
                                   │  摄像头   │
                                   │  实时采集  │
                                   └──────────┘
```

**数据流向：**
- 手机端采集人脸照片 → 上传到 Windows 后台
- Windows 后台存储人脸信息，下发注册指令到树莓派
- 树莓派从摄像头实时检测人脸 → 提取特征 → 与本地特征库比对 → 识别结果通过 UART 发给 STM32
- STM32 根据识别结果执行后续动作（开门、亮灯、报警等）

## 二、树莓派 4B 端（核心识别引擎）

### 2.1 职责

树莓派是整个系统的核心，承担以下工作：

1. **摄像头实时采集** — USB 或 CSI 摄像头持续取流
2. **人脸检测** — 在画面中定位所有人脸的位置和 5 个关键点
3. **人脸对齐** — 将检测到的人脸通过仿射变换校正为 112×112 标准正脸
4. **特征提取** — 用 MobileFaceNet 提取 512 维特征向量
5. **特征比对** — 与本地特征库中所有已注册人员做余弦相似度匹配
6. **结果输出** — 识别到的人名/ID/置信度通过 UART 发给 STM32
7. **接收指令** — 从 STM32（或 Windows）接收注册/删除用户等指令

### 2.2 AI 模型方案

采用 InsightFace 的两模型管线，推理框架使用 **ncnn**：

| 步骤 | 模型 | 输入 | 输出 |
|------|------|------|------|
| 人脸检测 | SCRFD (det_500m) | 任意尺寸 BGR 图像 | bbox + 5关键点 + 置信度 |
| 特征提取 | MobileFaceNet (w600k_mbf) | 112×112 BGR 图像 | 512 维归一化特征向量 |

**比对方式：** 两个 512 维向量做点积（L2 归一化后等价于余弦相似度），阈值 0.4 以上判定为同一人。

### 2.3 推荐技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 操作系统 | Raspberry Pi OS Lite 64-bit | 无桌面，省内存，aarch64 |
| 推理引擎 | **ncnn**（腾讯开源） | 专为 ARM 优化，支持 NEON 加速，已编译通过 |
| 图像处理 | OpenCV 4.x（apt 安装） | 摄像头采集、仿射变换、图像预处理 |
| 编程语言 | C++11/17 | 性能关键路径，CMake 构建 |
| 串口通信 | WiringPi 或原生 Linux 串口 | /dev/serial0，连接 STM32 |
| 配置解析 | nlohmann/json（header-only） | config.json 解析 |
| 自启服务 | systemd | 开机自动运行 |

**备选方案：** 如果 ncnn 自定义层问题彻底无法解决（目前 SCRFD 的 Shape/Gather 算子 pass-through 不准确导致推理崩溃），可以降级使用 **Python + onnxruntime** 方案，verify.py 已验证可用，在树莓派上预计 2-5 FPS，功能完整但性能较低。

### 2.4 软件架构

采用四线程模型，对应树莓派 4B 的四核 Cortex-A72：

```
线程1: 摄像头采集 → FrameQueue(容量1,只保留最新帧)
线程2: AI推理     → 取帧 → SCRFD检测 → 对齐 → MobileFaceNet提取 → 特征库比对 → ResultQueue
线程3: UART发送   → 从ResultQueue取结果 → 编码成帧协议 → 写串口
线程4: UART接收   → 读串口字节 → 拼帧解析 → 处理STM32指令
```

关键设计原则：
- 帧队列容量为 1，推理慢时自动丢弃旧帧，永远用最新帧
- 推理结果包含：识别到的人员 ID+姓名+置信度 / 检测到但未识别 / 未检测到人脸
- 每 5 秒发送一次心跳帧，保持与 STM32 的连接状态同步

## 三、STM32 端（通信与执行）

### 3.1 职责

1. **接收识别结果** — 从树莓派通过 UART 接收人脸识别结果帧
2. **解析协议帧** — 按帧协议解码，校验完整性
3. **执行动作** — 根据识别结果执行相应的硬件操作
4. **上传指令** — 向树莓派发送注册/删除/查询等控制指令

### 3.2 推荐技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| MCU | STM32F103C8T6 | Cortex-M3, 64KB SRAM, 128KB Flash |
| RTOS | FreeRTOS | 已集成，多任务调度 |
| 标准库 | STM32 FWlib 3.5 | 外设驱动 |
| 通信接口 | USART2 (PA2-TX, PA3-RX) | 115200-8-N-1, 连接树莓派 GPIO14/15 |
| 开发环境 | Keil MDK-ARM | .uvprojx 工程 |

### 3.3 帧协议

```
┌──────┬──────┬──────┬──────────┬──────┬──────┬──────┐
│ 帧头  │ 命令  │ 方向  │ 数据长度  │ 数据  │ 校验  │ 帧尾  │
│ 1B   │ 1B   │ 1B   │ 2B(H-L)  │ 变长  │ 1B   │ 1B   │
│ 0xAA │ CMD  │ DIR  │ LEN      │ DATA │ XOR  │ 0x55 │
└──────┴──────┴──────┴──────────┴──────┴──────┴──────┘

方向: 0x01=Pi→STM32, 0x02=STM32→Pi
校验: CMD ^ DIR ^ LEN_H ^ LEN_L ^ DATA[0] ^ ... ^ DATA[n-1]
转义: 数据区出现 0xAA/0x55 → 替换为 0xBB + (原字节^0xFF)
      0xBB 自身 → 替换为 0xBB + 0x44
```

**Pi → STM32 命令：**
| 命令字 | 含义 | 数据示例 |
|--------|------|----------|
| 0x10 | 识别成功 | "001,张三,0.92" |
| 0x11 | 检测到人脸但未识别 | 空 |
| 0x12 | 画面中无人脸 | 空 |
| 0x13 | 多人脸（>1 人同时出现） | "3" (人脸数量) |
| 0x1F | 心跳 | 空，每 5 秒 |

**STM32 → Pi 命令：**
| 命令字 | 含义 | 数据示例 |
|--------|------|----------|
| 0x20 | 开门/执行动作确认 | 空 |
| 0x21 | 注册新用户 | "001,张三" |
| 0x22 | 删除用户 | "001" |
| 0x23 | 查询库状态 | 空 |

### 3.4 已完成 / 待完成

**已完成：**
- FreeRTOS 环境搭建（静态内存分配，stack overflow / malloc fail 钩子）
- USART2 初始化（115200-8-N-1，RXNE 中断）
- ISR 中接收字节放入 FreeRTOS 队列
- UART 接收任务 + 简单状态机（8 字节帧解析 + 校验和验证）
- PA0 LED 指示

**待完成：**
- 将当前简单的 8 字节测试协议替换为上方完整帧协议（含转义处理）
- 实现各命令字的 handler（识别成功时亮绿灯、陌生人亮红灯、无人脸熄灯等）
- 实现 Pi 下发的心跳超时检测（超时则判定 Pi 离线，进入安全状态）
- UART 发送函数（向 Pi 回复 ACK 或上传指令）
- 具体动作逻辑（GPIO 控制继电器、蜂鸣器、LED 等，待用户确定需求后细化）
- 硬件看门狗（IWDG），防止程序跑飞

## 四、Windows 后台端

### 4.1 职责

1. **接收手机端上传的人脸照片** — 提供 HTTP API 接收图片
2. **人脸注册管理** — 存储用户信息（姓名、工号、人脸照片），维护人员数据库
3. **特征提取与下发** — 调用 Python 推理脚本提取人脸特征，将特征向量文件通过 SCP/SFTP 下发到树莓派
4. **管理界面（可选）** — Web 页面查看注册人员列表、识别日志等
5. **与树莓派通信** — 通过网络（SSH/自定义 TCP）向树莓派下发注册/删除指令

### 4.2 推荐技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 后端框架 | **FastAPI**（Python） | 轻量异步框架，自带 Swagger 文档，适合中小型后台 |
| 数据库 | SQLite | 零配置，单文件，人员数量不大无需 MySQL/PostgreSQL |
| 图像存储 | 本地文件系统 | 按用户 ID 分目录存放原始照片 |
| 推理调用 | 复用 verify.py 的 detect/extract 函数 | 提取特征向量 |
| 文件传输 | paramiko (SSH/SFTP) | 将 .bin 特征文件传到树莓派 |
| 前端（可选） | Vue.js + Element Plus | 轻量管理页面 |
| 部署 | 直接运行 Python 脚本 或 NSSM 注册为 Windows 服务 | 开机自启 |

### 4.3 核心功能

**API 设计：**
```
POST /api/register    — 手机端上传照片 + 姓名，后台提取特征，下发到树莓派
GET  /api/users       — 查询所有已注册用户
DELETE /api/users/{id} — 删除用户，同步通知树莓派
GET  /api/logs        — 查询识别日志（树莓派回传或后台记录）
POST /api/sync        — 手动触发特征库全量同步到树莓派
```

**下发流程：**
```
手机上传照片 + 姓名
  → Windows 后台保存原图
  → 调用推理脚本提取 512 维特征
  → 保存 .bin 特征文件
  → 通过 SCP 传到树莓派 features/ 目录
  → 树莓派 FeatureDB 热加载新特征（监控文件变化或接收指令）
```

- 全部待开发。建议优先做核心 API（注册 + 下发），管理界面后续补充。

## 六、开发顺序建议

```
第一阶段 — 核心管线打通（当前优先）
  □ 树莓派：解决 ncnn 推理崩溃，或确定用 Python+onnxruntime
  □ 树莓派：摄像头采集 + 实时推理 + 特征库 + 终端输出识别结果
  □ 树莓派：UART 帧协议编解码 + 发送/接收线程
  □ STM32：实现完整帧协议 + 命令处理 + 动作执行

第二阶段 — 前后端联通
  □ Windows 后台：FastAPI + SQLite + 注册/查询 API
  □ Windows 后台：特征提取 + SCP 下发到树莓派
  □ 树莓派：网络监听端口，接收 Windows 下发的注册指令

第三阶段 — 移动端 + 完善
  □ 手机小程序：拍照 → 上传 → Windows 后台
  □ Windows 后台：管理页面（可选）
  □ 整机联调 + 长时间稳定性测试
  □ systemd 自启 + 看门狗
```
